The Problem & Our Solution

The Problem: Documentation Burden in Clinical Care

Clinicians often spend more time documenting visits than interacting with patients. Doctor–patient conversations contain rich diagnostic detail, but they arrive as unstructured speech—difficult to store consistently, search, or feed into analytics and EHR workflows.

Our Solution: An Automated Documentation Pipeline

This system records encounters through a lightweight web interface, transcribes audio with OpenAI Whisper, and uses Google Gemini to produce both a readable narrative summary and schema-aligned structured clinical data. Results land in a normalized Neon PostgreSQL database with foreign-key integrity—supporting reprocessing, auditing, and downstream integration without altering the raw conversation.

Core Features

In-Browser Audio Capture

A simple recording UI built with the MediaRecorder API lets clinicians capture consultations without leaving the browser. Optional patient IDs tie new audio to returning visits.

Speech to Text

Uploaded audio is transcribed locally with OpenAI Whisper, producing a clean text transcript linked to a conversation record in the database.

Dual LLM Output

Gemini generates a concise clinical summary for human review and a structured JSON object aligned to our relational schema—symptoms, treatments, medical history, surgeries, and more—so the same visit is usable both narratively and analytically.

Relational Storage

Structured outputs are stored as raw JSON and decomposed into normalized tables (patient, visit, conversation, symptoms, treatments, etc.) with enforced referential integrity on Neon PostgreSQL.

Technical Architecture

End-to-End Pipeline

  1. Audio capture — Web UI records clinical encounters.
  2. Transcription — Whisper converts speech to text.
  3. Summarization & structuring — Gemini produces narrative and schema-constrained JSON.
  4. Persistence — PostgreSQL stores conversation, summaries, and normalized clinical entities.

Tech Stack

  • Backend: Python, Flask, Whisper, Google Gemini API
  • Database: Neon PostgreSQL, normalized schema with SQL constraints
  • Frontend: HTML/CSS/JavaScript, MediaRecorder API

Limitations & Future Work

The current prototype does not include a clinician review step before final insertion, and some temporal fields remain free text. Future work includes editable review layers, stronger validation, confidence scoring, and authentication with audit logging.
